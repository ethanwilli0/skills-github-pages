# DNS (Domain Name System)
A phonebook of your network and the internet. It translates human-friendly names such as *server01.corp.local* into IP addresses that machines actually use. 

## Why DNS is critical
1. Name resolution is foundational
	Almost every services depends on DNS: authentication, files shares, email, SaaS apps, printers, imaging servers, etc.
	If DNS is sow or wrong, users experience:
		Login taking forever - The internet is down - I can't reach the file server
2. Active Directory literally requires DNS
	Without functional DNS, AD can't locate domain controllers, apply GPOs, authenticate users, discover services
3. Central control for your network's hostnames
	DNS gives you a single place to manage server names, service records, aliases/CNAMEs, and split-horizon DNS (internal vs external version of the same name)
4. Troubleshooting power
	DNS frequently hides behind symptoms that look unrelated. Understanding DNS lets you fix issues like
	- Clients using public DNS instead of AD-integrated DNS
	- Duplicate or stale records
	- DHCP not updating DNS
	- Broken conditional forward
	- Slow logins due to unreachable DNS servers
	- Services failing because CNAMES were changed incorrectly
5. Security & hygiene
	DNS is used to improve network safety.
	- blocking malicious domains 
	- using DNSSEC
	- internal DNS filtering
	- logging to track abnormal traffic
	A lot of modern SOC tooling uses DNS logs to detect early compromise
6. Integration with DHCP
	In an AD environment, DHCP + DNS are closely linked:
	- DHCP can dynamically update DNS A and PTR records
	- Reservations ensure stable names for servers or appliances
	- DNS scavenging keeps things clean
	This is why knowing one helps you understand the other
